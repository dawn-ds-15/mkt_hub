# Yêu cầu BE — Dashboard loại trừ toàn bộ dữ liệu soft-delete

> Ngày: 29/08/2026
> Nguồn: FE rà soát tab Dashboard, phát hiện các số tổng hợp do BE trả có thể vẫn đang tính cả bản ghi đã xóa mềm (soft-delete `archivedAt`). FE yêu cầu đảm bảo **mọi số liệu Dashboard chỉ tính trên dữ liệu còn hoạt động** (`archivedAt IS NULL`).

---

## 1. Hiện trạng

Tab Dashboard (`/`) hiển thị các số tổng hợp từ backend:

| Vùng hiển thị | Nguồn API | FE có tự lọc soft-delete? |
|---------------|-----------|---------------------------|
| KPI Cards (Raw Leads, MQL, SQL, Closed Deal, Pipeline…) | `GET /v1/dashboard/overview` → `kpiCards` | ❌ Không |
| Funnel Chuyển đổi | `GET /v1/dashboard/overview` → `funnel` | ❌ Không |
| Activities (hoạt động Marketing) | `GET /v1/dashboard/overview` → `activities` | ❌ Không |
| Task Status (thống kê trạng thái công việc) | `GET /v1/dashboard/overview` → `taskStatus` | ❌ Không |
| Total Progress | `GET /v1/dashboard/overview` → `progress.totalPct` | ❌ Không |
| ROAS / Tổng chi phí | `GET /v1/expenses/overview` → `metrics` | ❌ Không |
| Alerts (quá hạn / sắp hạn) | `GET /v1/dashboard/overview` → `alerts` | ✅ Có (FE lọc `tasks`) |
| Project Progress | `GET /v1/dashboard/overview` → `progress.projects` | ✅ Có (FE lọc `projects`) |

> Kết luận: phần lớn số liệu Dashboard phụ thuộc backend. Nếu backend tính KPI/funnel/taskStatus/expense mà **không loại trừ `archivedAt`**, Dashboard sẽ hiển thị số liệu của các bản ghi đã xóa → sai lệch báo cáo.

---

## 2. Yêu cầu

### 2.1 Nguyên tắc chung (bắt buộc)

Mọi query và mọi phép **tính tổng/đếm/trung bình** phục vụ Dashboard phải mặc định `archivedAt IS NULL` (hoặc condition tương ứng), nghĩa là:

1. **Task:** loại trừ task có `archivedAt != null` trước khi tính:
   - số task theo trạng thái (`taskStatus.byStatus`),
   - số task hoàn thành/đang làm (`taskStatus`),
   - alerts `overdue` / `upcoming` (FE đã lọc, yêu cầu BE lọc luôn cho chắc),
   - `progress` của dự án (done/total).
2. **Project:** loại trừ project đã xóa khi tính `progress.totalPct` và danh sách `progress.projects`.
3. **KPI / Funnel / Activities:** nếu các số này được tổng hợp từ các bảng `KpiWeekly`, `Event`, `Opportunity`, `ClosedDeal`, `Task`, `ExpenseRecord`… thì tất cả phải lọc `archivedAt IS NULL` trên từng bảng nguồn.
4. **Expense** (`/v1/expenses/overview`): loại trừ `ExpenseRecord` đã xóa khi tính `totalExpense`, `cac`, `roas`, `totalWonValue`.

### 2.2 Các endpoint cần rà soát

| Endpoint | Phần cần đảm bảo lọc soft-delete |
|----------|---------------------------------|
| `GET /v1/dashboard/overview` | `kpiCards`, `funnel`, `activities`, `taskStatus`, `progress`, `alerts` |
| `GET /v1/expenses/overview` | `metrics.totalExpense`, `cac`, `roas`, `totalWonValue` |

### 2.3 Hành vi kỳ vọng sau khi fix

- Xóa mềm 1 task/1 deal/1 expense/1 project → mọi số tổng hợp tương ứng trên Dashboard **giảm ngay** đúng với số lượng vừa xóa.
- Không có bất kỳ vùng nào trên Dashboard còn hiển thị số liệu của bản ghi đã xóa.
- BE chủ động thêm filter, **không phụ thuộc** FE phải tự lọc từng phần.

# Yêu cầu BE — Nhập chi phí: hỗ trợ hạng mục "Thêm hạng mục" (`__custom__`)

> Mục này thuộc cùng ngày 29/08/2026, bổ sung thêm vào file yêu cầu hôm nay.

---

## 1. Hiện trạng

- Tab Nhập chi phí (`ExpenseEntryForm`) dropdown Hạng mục hiện có: `POSM`, `Quà tặng`, `Ấn phẩm in`, `Khác` (`__other__`), và **mới thêm** `Thêm hạng mục` (`__custom__`).
- Khi FE chọn **`__custom__`**:
  - Người dùng nhập tay: Mô tả, VAT (%), Đơn giá (sau VAT), SL KH, SL Thực, Ghi chú; Thành tiền KH/TT tự tính = Đơn giá × SL.
  - Khác hạng mục `__other__` (SL KH/Thực bị khóa = 1), với `__custom__` SL KH/Thực được nhập tay.
- FE gửi `POST /v1/expenses/{id}/lines` (hoặc PATCH) với payload:
  ```
  {
    "name": "<mô tả người dùng nhập>",
    "categoryId": "__custom__",
    "inventoryItemId": null,
    "isCustom": true,
    "plannedQuantity": <số nhập tay>,
    "actualQuantity": <số nhập tay>,
    "vatRate": <số nhập tay>,
    "actualUnitPrice": <đơn giá nhập tay>,
    "note": ""
  }
  ```

## 2. Yêu cầu BE

1. **Chấp nhận `categoryId = '__custom__'`** (và `'__other__'` hiện tại) như giá trị hợp lệ của trường hạng mục — không gắn với bảng `InventoryCategory`/`InventoryItem` nào.
2. **Không ép buộc `inventoryItemId`** khi `isCustom = true` — lưu được `plannedQuantity`/`actualQuantity` bất kỳ (không ép = 1, tránh bỏ số người dùng nhập).
3. **Không tự áp đặt đơn giá từ item** khi `isCustom = true` — dùng `actualUnitPrice` người dùng gửi.
4. Khi **đọc lại** (`GET /v1/expenses/{id}` / `getExpenseList`), trả về các field trên để FE render đúng:
   - `name`, `categoryId = '__custom__'`, `inventoryItemId = null`, `isCustom = true`,
   - `plannedQuantity`, `actualQuantity`, `vatRate`, `actualUnitPrice`, `note`.
5. **Tổng hợp chi phí** (`/v1/expenses/overview`, báo cáo) phải tính đúng các dòng custom này (bao gồm cả Total trong khối chi phí).
